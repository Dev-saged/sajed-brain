# بدء مشروع مورد MAWRED — الوحدة M0

## الطلب
- مشروع جديد مربوط بـDev-saged/Morud، بلا برمجة عشوائية ولا بناء كل شيء دفعة واحدة؛ كل وحدة تكتمل وتنجح اختباراتها قبل التالية؛ التسليم النهائي كامل ومتكامل.
- أرفق وثيقة SRS شاملة (23 قسماً): منصة توريد بالجملة للمحلات في غزة — Android + Web + PWA + لوحة إدارة + خادم + مالية + توصيل + إشعارات.

## ما نُفّذ
- `Morud→docs/SRS` (النص كما هو)، `Morud→docs/requirements-checklist` (متطلبات مرقمة مربوطة بالوحدات)، `Morud→docs/architecture` (انحرافات D1–D10)، `Morud→docs/data-model` (مجموعات Firestore مقابل جداول SRS + ERD + فهارس)، `Morud→docs/roadmap` (M0–M14 بشروط إغلاق).
- `spec/`: 56 صلاحية، 9 أدوار، آلة حالات بـ14 حالة و30 انتقالاً (guards/effects)، تصنيفات ووحدات وإعدادات أولية.
- `tests/spec.test.mjs`: 18 اختبار اتساق (node:test بلا تبعيات) + CI `spec.yml` أخضر على GitHub.
- ملفات ذاكرة المشروع: CLAUDE.md، `.claude/session-handoff.md`، `docs/repo-map.md`.

## القرارات
- قرار ساجد: Kotlin + Compose بدل Java المذكورة في الوثيقة.
- قرار ساجد: Firebase + Cloudflare Workers بدل Spring Boot + PostgreSQL (بلا سيرفر مدفوع).
- العميل يقرأ Firestore بقواعد صارمة ولا يكتب أبداً؛ كل كتابة عبر Worker (RBAC + تدقيق + idempotency).
- المال بالأغورة int والكمية qtyMilli؛ دفتر append-only؛ R2 للصور؛ React + TS للويب كما في الوثيقة.

## الأخطاء والدروس
- `node --test tests/` يفشل على Node 22 (يعامل المجلد كملف) ← `node --test tests/*.test.mjs`.
- رسالة ساجد الأولى بلا وصف للفكرة ← سُئل بدل التخمين؛ الوثيقة وصلت في الرسالة التالية.

## التالي
- M1: نواة المنطق في `worker/src/domain` (المال، الوحدات، آلة الحالات، المهلة، الدفتر، التسعير والعروض، البحث العربي) مع سيناريوهات SRS 19.3 الخمسة.

## تكملة — M1 وM2 (عمل متواصل بطلب ساجد)
- قرار ساجد: الاستمرار دون توقف، رفع وتسجيل كل مرحلة، تحديث README باستمرار، واختبار كل مرحلة قبل التالية.
- M1 نواة المنطق (`worker/src/domain`): المال بالأغورة، الكميات، الكتالوج، التسعير، العروض الخمسة بلا تكديس، آلة الحالات، الصلاحيات، المهلة بتوقيت غزة مع الصيفي، الدفتر والإلغاء والحد الائتماني، البحث العربي — 58 اختباراً تشمل سيناريوهات SRS الخمسة.
- M2 أساس الخادم: Firestore REST بمعاملات، تحقق ID token بـWebCrypto، الدخول الموحد بحد محاولات، RBAC من وثيقة المستخدم في كل طلب، تدقيق، idempotency داخل المعاملة — 97 اختباراً، تغطية 99.9%، تحزيم wrangler.
- خطأ: CI فشل لأن typecheck لم يُشغَّل على ملفات الاختبار محلياً ← سكربت `npm run check` (typecheck + coverage + bundle) قبل كل commit.
- npm 10 + vitest 4 يفشل بـ`edgesOut` ← `legacy-peer-deps=true` في `.npmrc`.

## تكملة — M3 وM4 وM5
- M3 قواعد Firestore: لا كتابة من أي عميل، القراءة بـclaims (rp/k/sh)، 13 اختباراً على محاكي Firestore (Java 21) + CI.
- M4 إدارة النظام: المستخدمون (لا منح لما لا يملكه المانح، super_admin لمالكه فقط، آخر مالك محمي)، الأدوار والصلاحيات المضافة وقت التشغيل، المحلات وموظفوها والائتمان، الكتالوج وSKU الفريد، رفع الصور المفرّغة (فحص ألفا بالبايتات) إلى R2، الإعدادات بتحقق صارم، التهيئة الأولى مرة واحدة.
- M5 الطلبات والإشعارات: إرسال بتسعير الخادم ومنع التكرار، آلة الحالات بالآثار المالية في نفس المعاملة (فاتورة عند التأكيد، تحصيل عند التسليم، إلغاء بإشعار دائن، مرتجع)، تعديل الإدارة وموافقة المحل، المسودات، صندوق الإشعارات وFCM مع إعادة المحاولة وحذف الرموز التالفة. 136 اختباراً للخادم.
- درس: معاملة داخل معاملة علّقت قاعدة الذاكرة ← وثيقة منع التكرار تُكتب داخل معاملة العملية نفسها (`createAccountOnce`).
