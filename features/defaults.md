# الميزات الافتراضية — تُبنى دون أن يطلبها ساجد
_كل فكرة تُحلَّل من كل الزوايا، ثم تُضاف هذه الميزات تلقائياً حين تنطبق. يُذكر في الموجز ما أُضيف ولماذا، ويُسأل ساجد فقط إن كانت الإضافة تغيّر ميزة موجودة._

## قاعدة الاستنتاج (مثال ساجد)
لوحة تحكم ⇒ يوجد مستخدمون ⇒ أدوار (مدير/موظف/…) ⇒ دخول باسم مستخدم ⇒ استعادة كلمة المرور ⇒ "تذكرني" ⇒ سجل نشاط ⇒ صلاحيات على السيرفر.
اسأل نفسك لكل ميزة: من يستخدمها؟ ماذا لو فشل النت/الكهرباء؟ ماذا لو ضاعت البيانات؟ كيف يعرف المستخدم أن شيئاً حدث؟ ماذا يحتاج من صلاحيات؟

## 1) الهوية والأدوار
- دخول باسم مستخدم أو هاتف + كلمة مرور (Firebase Auth: email صناعي `user@shop.local` عند الاسم فقط).
- استعادة كلمة المرور: بريد إن وُجد، وإلا المدير يعيد التعيين من لوحته (Worker إداري).
- "تذكرني": جلسة Firebase مستمرة؛ بدونه تسجيل خروج بعد إغلاق التطبيق. Android: DataStore مشفّر لعلم التذكّر فقط، لا كلمات مرور.
- أدوار: owner / manager / employee (+ viewer عند الحاجة) في custom claims أو `users/{uid}.role`، وSecurity Rules تفرضها؛ الواجهة تخفي فقط.
- قفل التطبيق ببصمة/PIN اختياري، وسجل تدقيق (من، متى، ماذا) لكل تعديل حساس.

## 2) التحديث التلقائي بمجلد منظم (Android)
- الفحص: `features/auto-update.md` (latest-build + versionCode).
- التنزيل بـ DownloadManager أو WorkManager إلى مجلد التطبيق الخاص — لا يحتاج صلاحية تخزين:
  ```
  Android/data/<pkg>/files/
    updates/   ← APK الجديد: <app>-v<versionName>-<code>.apk
    backups/   ← النسخ الاحتياطية اليومية
    exports/   ← Excel/PDF المصدّرة
    logs/      ← سجل أخطاء مدوّر (آخر 7 أيام)
  ```
- قبل التنزيل: إن وُجد في `updates/` ملف بنفس versionCode وحجمه = حجم الأصل ⇒ ثبّته مباشرة بلا تنزيل. تنزيل مستأنف (Range) عند انقطاع النت.
- تحقق SHA-256 (من body الـRelease) قبل التثبيت؛ تثبيت عبر FileProvider + `ACTION_VIEW` (أو PackageInstaller session).
- بعد التثبيت: عند أول تشغيل بالإصدار الجديد يُحذف كل ما في `updates/` (مقارنة versionCode المحفوظ بالحالي) — لا تنزيل من الصفر كل مرة ولا ملفات قديمة تأكل المساحة.
- صلاحية `REQUEST_INSTALL_PACKAGES` مع شاشة شرح قبل فتح إعداد "مصادر غير معروفة".
- الويب/PWA: service worker يكتشف الإصدار الجديد ⇒ بانر "تحديث" ⇒ `skipWaiting` + إعادة تحميل.

## 3) النسخ الاحتياطي اليومي
- WorkManager دوري يومي (شرط: بطارية غير منخفضة) ⇒ JSON مضغوط مشفّر (AES-GCM بمفتاح Keystore) في backups/ باسم backup-<التاريخ>.json.gz.
- الاحتفاظ: يُحذف كل ما هو أقدم من 3 أيام بعد نجاح النسخة الجديدة فقط (لا تحذف القديم إن فشل الجديد). يبقى دائماً آخر نسخة ناجحة على الأقل.
- استعادة من الإعدادات + مشاركة/تصدير النسخة (واتساب/Drive) يدوياً. مع Firestore: النسخة المحلية تكميلية، والسحابة هي المصدر.
- الويب: IndexedDB ⇒ ملف JSON بزر + تذكير أسبوعي.

## 4) الإشعارات
- قنوات منفصلة (تحديثات، تذكيرات، نشاط، تصدير) بأسماء عربية؛ طلب `POST_NOTIFICATIONS` (Android 13+) في لحظة الحاجة لا عند التشغيل.
- أمثلة: تحديث جاهز، نسخة احتياطية فشلت، دين مستحق، انتهاء جلسة، تقدّم التصدير (foreground).
- FCM فقط عند وجود سحابة؛ وإلا إشعارات محلية مجدولة (AlarmManager/WorkManager). الويب: Notification API + push عبر SW عند الحاجة.

## 5) الصلاحيات — الحد الأدنى، كلٌّ في وقته
| الحاجة | الصلاحية | ملاحظة |
|---|---|---|
| ملفات التطبيق/النسخ/التحديث | لا شيء | المجلد الخاص لا يحتاج صلاحية |
| حفظ في التنزيلات العامة | MediaStore (بلا صلاحية من 29+) | SAF لاختيار مكان |
| صور/ملفات المستخدم | Photo Picker / SAF | لا READ_EXTERNAL_STORAGE |
| تثبيت التحديث | REQUEST_INSTALL_PACKAGES | شاشة شرح أولاً |
| إشعارات | POST_NOTIFICATIONS | 13+ |
| تذكيرات دقيقة | SCHEDULE_EXACT_ALARM | فقط إن لزم |
| SMS/كاميرا/موقع | حسب الميزة | rationale عربي + مسار رفض محترم |
كل رفض له مسار بديل وشرح، وزر "افتح الإعدادات" عند الرفض الدائم.
